# 词汇回忆室：跨 Agent 工作约定

这份 Skill 是项目决策的精简记录，不是聊天逐字稿。每次先以用户当前要求为准，再核对仓库和现有资料；不要把历史约定误当成一次新的上传、删除或日历授权。项目仓库为 `zhenghuiyu06/vocabulary-recall-room`。本机常见检出路径是 `outputs/kaoyan-vocab-recall`，但新环境中应先定位仓库，不能依赖这个路径一定存在。

## 背词程序的稳定规则

- 主流程为“看英文 → 自己回忆中文 → 点击揭晓”，反馈分“熟悉 / 模糊 / 不会”。随机打乱、保存历史和到期进度。
- 复习阶段依次为“初见 → 12H → 1D → 3D → 7D”。不要让“到期复习”按钮意外重置已有阶段。
- 程序内的长期记忆库：通过 7D，且最近连续 3 次间隔回忆均选“熟悉”；“模糊”或“不会”中断连续记录。入库后不再进入常规复习，但保留恢复复习入口。
- 纸质词表的规则与程序评分分开：**同一单词的勾累计 ≥3 个**就从待加强词表剔除／可进入长期记忆；黑笔、蓝笔都计入。圈释义、下划线、页边学习笔记不是勾。0～2 个勾仍保留复习。照片识别结果应允许逐行人工校对。
- 浏览器学习进度默认只在本机 `localStorage`，保留 JSON 备份/恢复能力。不要假设 GitHub 会同步个人进度。

## 整理词表与 PDF

- 用户给出新词时，合并前先查重；不要默认“不会认得”就是做错题。中文释义优先阅读/翻译常见考义，但不能凭空声称有精确的真题频率统计。用户给出的释义与词序应尽量保留；疑似拼写笔误需标明或核对。
- 用户要求“新增”和“之前旧词”分开时，分区保留，不自行混排。只有在用户明确要求融合时才合并。
- 常用成品为 A4 双栏、英文＋中文释义、适合遮住中文背诵；行距留出手写空间，不要“当前状态”列。标题不加“考研”二字。日期标在每页右上角。用户通常希望成品可从“下载”文件夹直接取得。
- 原 PDF、源词表和已交付文件不要覆盖。新筛选先记录规则和剔除数量，保持未剔除词的原顺序与释义；生成后核对词数、页数、中文字体及逐页视觉布局。创建/编辑 PDF 时遵循可用的 PDF Skill。
- 2026-10-04 的一次已完成案例：193 词的纸质“本次新增”表，经三张照片逐行数勾，剔除 82、保留 111。它是历史快照，不代表用户当前所有词库；详见 [历史与文件定位](references/history.md)。

## 程序与发布边界

- 先检查当前仓库状态、远端分支和数据格式，再编辑。改动后按风险运行相关测试、检查导出结果，再提交或推送用户要求的内容。
- 公开仓库默认不包含原始照片、浏览器个人学习进度、运行日志、临时文件或生成的个人 PDF。用户明确指定某一资料公开时，才单独纳入；不要把“把记录传到 GitHub”泛化为上传整段聊天或全部私人资料。
- 如果用户要日历复习提醒，遵守“早上 10:00 之后”的时段偏好；具体日历写入、重复规则和授权需按该次请求及可用日历工具处理，不能仅凭此 Skill 自行创建事件。
